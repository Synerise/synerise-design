# Un-tokenised components — module vs semantic decision

> Companion to [`TOKENISATION_STATUS.md`](./TOKENISATION_STATUS.md) and
> [`TOKEN_USAGE_BY_COMPONENT.md`](./TOKEN_USAGE_BY_COMPONENT.md). Lists every component package that has
> **not** been tokenised yet, so we can decide — per component — whether it should get a **dedicated
> module-token namespace defined upstream** (in `design-tokens`) or be **tokenised directly against the
> semantic layer** (`--ds-color-*` / `--ds-shadows-*` / `--ds-opacity-*`).
>
> **Snapshot 2026-07-20.** Generated by scanning each package's `src` `.ts`/`.tsx` (excluding
> `__specs__`/`.spec.`/`.test.`/`.figma.`/`.stories.`/`dist`/`lib`) for `theme.palette` refs and applied
> `var(--ds-*)` tokens. A package counts as **tokenised** once it applies any `--ds-*` var; the 29
> tokenised components are excluded here (see the status doc).

## How to use this

Each row in the decision table has two checkboxes — **tick the applicable box(es)** (a component can need
both: module tokens for its own surface *and* semantic for the rest):

- **☐ Module** — the component has enough distinct, reusable, brand-controlled surface/states that UX
  should define a `--ds-<component>-*` namespace for it upstream. We then consume those (like the 29
  already-tokenised components). *These are the rows to discuss.*
- **☐ Semantic** — the component is a composition of already-tokenised primitives and/or simple chrome;
  tokenise its own styling directly with semantic tokens, no new module namespace needed. *These are
  usually quick approvals.*

Record a decision by ticking a box (replace `[ ]` with `[x]`); use the **Module notes** / **Semantic
notes** columns for specifics — which existing tokens/primitives to reuse, follow-ups, or things to
remove from the code.

**Reminders:** this repo is **consume-only** — we never author module tokens here; a "Module" decision is
a request to UX/Token Studio. Never use primitives (`--ds-color-grey-700`) directly. Icons inherit
`currentColor` from the parent's CSS `color`.
